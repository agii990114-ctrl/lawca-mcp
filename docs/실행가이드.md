# 실행 가이드

개발 환경 실행, 컨테이너 운영, 시험 방법을 모았습니다. 프로젝트 소개는 [README](../README.md), 설계 근거는 [기획서_v2.md](../기획서_v2.md), 겪은 문제는 [트러블슈팅](트러블슈팅.md)을 참고하세요.

> **모든 데이터는 가상의 더미입니다.** 사건·당사자·연락처·계좌 등은 전부 지어낸 값이며 실제 인물·사건과 무관합니다. 주민등록번호 형식 값 등은 마스킹 시험용 가짜입니다. 결과물은 변호사가 검토하는 초안이며 법률 자문이 아닙니다.

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `server/` | MCP 서버(Python). 도구 7개: `list_matters`, `search_documents`, `get_document`, `check_citation`, `get_case`, `get_statute`, `search_cases`. 하이브리드 검색, 서버 측 마스킹, 감사 로그, 법제처 어댑터·조회 중계(`law_gateway.py`) |
| `backend/` | 웹 API(FastAPI): 로그인·역할(관리자/변호사/사무원)·접근 그룹, 사건·문서, **문서 업로드(개별 파일·ZIP)와 인제스트 워커**(파싱·OCR → 청킹 → 로컬 임베딩 → 저장), 개인 토큰 발급 |
| `frontend/` | 웹 화면(React + TypeScript + Vite): 로그인, 업로드, 처리 현황·검토, 사건(관련자 등록), 문서, AI 연결, 관리 |
| `db/` | PostgreSQL + pgvector 스키마(행 수준 보안 포함), 마이그레이션 001~006, 더미 적재·검증 스크립트 |
| `dummy-data/` | 가상 사건 32건·문서 71건(준비서면 중심, 쟁점 태그·접근 그룹 포함) |
| `sample-case/` | 서면 초안 작성을 시험해 볼 수 있는 가상 사건 자료 묶음 |
| `eval/` | 평가 도구: 서면 초안 반복 시험(자동 채점), 에이전트 시나리오, 긴 서면·스캔·OCR 비교 시험, 법제처 실연동 확인 |
| `parse-test/` | 사전 실험: kordoc 파싱·OCR, 임베딩·검색·라우팅·리랭커 비교 |
| `docs/` | 트러블슈팅 기록, 실행 가이드 |

## 빠른 시작 (개발용)

```bash
cp .env.example .env               # 개발용 비밀번호로 수정
docker compose up -d db            # DB만 (127.0.0.1:5433, 개발용 override). 전체 스택은 아래 '컨테이너로 실행'
python -m venv server/.venv && server/.venv/Scripts/python -m pip install -r server/requirements.txt
server/.venv/Scripts/python db/load_dummy.py     # 더미 적재 + 로컬 임베딩(약 7분, 최초 1회 모델 다운로드)
server/.venv/Scripts/python db/verify.py         # 스키마·RLS·권한 검증
server/.venv/Scripts/python server/tests/e2e.py  # MCP 종단 시험
```

### 웹 화면·업로드 (백엔드 + 프런트엔드)

```bash
python -m venv backend/.venv && backend/.venv/Scripts/python -m pip install -r backend/requirements.txt
(cd backend/tools && npm install)                      # 워커가 쓰는 kordoc(문서 변환·OCR)
(cd frontend && npm install && npm run build)          # frontend/dist 를 API가 같은 오리진으로 서빙
backend/.venv/Scripts/python db/migrate.py             # 백엔드용 스키마·역할 (.env 의 LAWCA_APP/WORKER 비밀번호 필요)
backend/.venv/Scripts/python -m backend.app.manage create-admin --user-id admin --name "관리자"   # 운영: 관리자 생성(비밀번호는 프롬프트)
# 개발용 계정(무작위 비밀번호는 .dev-credentials.txt, git 제외): python -m backend.app.manage seed-dev
backend/.venv/Scripts/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000   # API + 화면
backend/.venv/Scripts/python -m backend.app.worker     # 인제스트 워커(별도 프로세스, 여러 개 가능)
backend/.venv/Scripts/python -m pytest                 # 백엔드 시험 184개
```

## 컨테이너로 실행 (운영 권장)

| 컨테이너 | 역할 | 외부 통신 |
|---|---|---|
| `proxy` (Caddy) | 브라우저의 유일한 입구: https, 업로드 상한, 보안 헤더(CSP 등) | 가능 |
| `api` | FastAPI: 로그인·사건·문서·업로드 접수, 빌드된 화면 서빙 | **차단** |
| `worker` | 문서 변환·OCR·청킹·임베딩·저장(원문을 가장 많이 다룸) | **차단** |
| `mcp` | 에이전트용 MCP 서버. 프록시의 `/mcp`, 웹에서 발급한 **개인 토큰**으로 접속, 발급자의 접근 그룹 권한으로 동작 | **차단** |
| `law-gateway` | 법제처 공개 API 조회 전용 중계. DB 접근 없음, 인증값(`LAWCA_LAW_API_OC`)은 여기에만 있음. 검증된 사건번호·법령명·조문번호·검사를 통과한 검색어만 받음. `mcp`와는 내부 전용 네트워크(`lookup`)로만 연결 | 법제처 한 곳만 |
| `db` | PostgreSQL + pgvector, 접근 그룹 권한(RLS) 강제 | **차단** |
| `migrate` | (일회성) 스키마 마이그레이션·앱용 DB 계정 생성 — 소유자 비밀번호를 가진 유일한 앱 컨테이너 | 차단 |
| `fetch-models` | (일회성, 최초 1회) 임베딩·OCR 모델을 볼륨에 내려받기 | 가능 |

```bash
docker compose build
docker compose --profile setup run --rm fetch-models         # 최초 1회, 인터넷 필요(임베딩 모델 약 2.2GB + OCR 모델)
docker compose -f docker-compose.yml up -d                   # 운영: https 만 공개(127.0.0.1:8443). 개발은 -f 없이 up -d
docker compose -f docker-compose.yml run --rm migrate python -m backend.app.manage create-admin --user-id admin --name "관리자"
```

- 워커·API·MCP·DB는 `internal` 네트워크에만 붙어 **인터넷에 나갈 수 없다**(문서 원문이 사내 밖으로 나가지 않는다는 원칙을 인프라로 강제). 모델은 준비 단계에서 미리 받아 둔다. 판례 조회가 필요할 때만 `law-gateway`가 법제처로 나간다.
- 모든 앱 컨테이너는 비root(uid 10001)·읽기 전용 루트 파일시스템·`cap_drop: ALL`. 컨테이너마다 필요한 DB 비밀번호만 받는다(API는 소유자·워커 비밀번호가 없고, 중계는 DB 정보가 전혀 없다).
- 개발용 `docker-compose.override.yml`(자동 적용)은 DB 포트(127.0.0.1:5433)와 평문 HTTP(127.0.0.1:8081)를 추가로 연다. **운영에서는 `-f docker-compose.yml` 로 이 파일을 쓰지 않는다.**
- https 인증서: 기본은 Caddy 내부 CA(`tls internal`, 브라우저에 신뢰 등록 필요). 실제 도메인·사내 인증서는 `LAWCA_HOST`와 `deploy/Caddyfile`의 `tls` 줄을 바꾼다. 외부에 공개하려면 `LAWCA_BIND=0.0.0.0`.
- 볼륨: `lawca_pgdata`(DB), `lawca_uploads`(업로드 원본), `lawca_models`(모델), `caddy_data`. **백업 대상은 앞의 두 개**이며 함께 백업해야 일관된다.
- 백엔드 시험은 워커 컨테이너가 같은 DB의 업로드 작업을 집어 가지 않도록 `docker compose stop worker` 후 실행하는 것이 확실하다.
- 법제처 판례·조문 조회를 쓰려면 [법제처 국가법령정보 공동활용](https://open.law.go.kr)에서 Open API 인증값(OC)을 신청해 `.env`의 `LAWCA_LAW_API_OC`에 넣는다(비워 두면 판례·조문은 사무소 등록부로만 확인).
- 프런트 개발 서버는 `npm run dev`(포트 5173, `/api`를 8000으로 프록시). 운영에서는 **https 리버스 프록시 뒤에서** `LAWCA_COOKIE_SECURE=1`로 실행하고, 프록시에 요청 본문 상한을 설정하세요.

## AI 클라이언트 연결

변호사가 웹의 **AI 연결**에서 개인 토큰을 발급하고, 화면에 나오는 프로그램별 설정(Claude Code, Cursor, Gemini CLI, Codex)을 복사해 등록합니다. 자세한 방법과 제한은 [server/README.md](../server/README.md), 설정 예시는 `.mcp.json.example`을 참고하세요(개발용 stdio는 `LAWCA_USER_ID`).

연결한 뒤 이렇게 요청해 볼 수 있습니다.

```text
이 폴더의 사건 자료를 읽고 제1차 준비서면 초안을 작성해줘.
소멸시효 중단 사유로서 채무승인이 인정되는 기준에 관한 대법원 판례를 찾아서 사건번호·선고일·사건명을 표로 정리해줘.
대법원 2004다59959 판결의 판시사항과 판결요지를 읽고 3줄로 요약해줘.
```

## 알려진 한계

프로토타입 단계이며 합성 데이터와 소규모 시험에 근거한 결론입니다. 자세한 목록은 [트러블슈팅의 열린 문제](트러블슈팅.md)에 있습니다.

- 마스킹은 형식이 정해진 값, 당사자·변호사·등록된 관련자 이름, 역할어·호칭이 붙은 제3자 이름만 처리합니다. 역할어 없는 제3자 이름, 건물명만 있는 주소는 가리지 못합니다.
- 실제 한컴(HWP/HWPX)·법원 서식·실제 스캔본으로는 검증하지 못했습니다(합성 데이터와 DOCX·합성 스캔 PDF로만 시험).
- `check_citation`은 존재와 번호·선고일 일치, 조문 현행 여부, 판례 요지의 대략적 일치까지만 확인합니다. 판시 요지의 정확성은 변호사가 원문으로 대조해야 합니다. 법제처에 수록되지 않은 판례는 조회되지 않습니다.
- MCP 토큰은 탈취되면 만료·폐기 전까지 쓸 수 있는 베어러 비밀입니다(IP·기기 고정, MFA 없음). 호출 속도 제한은 서버 프로세스별 메모리 기준이라 여러 대로 늘리면 공유되지 않습니다.
- 임베딩은 CPU에서 약 1~1.5 청크/초라 대량 색인에는 GPU 또는 다중 워커가 필요합니다.
- ChatGPT·claude.ai 같은 웹 앱 커넥터는 서버 공개와 OAuth가 필요해 지원하지 않습니다.
- 웹: 업로드 원본의 저장 시 암호화·바이러스 검사 없음(볼륨 암호화·별도 검사 전제), MFA 없음, 로그인 잠금은 아이디 기준, 프런트엔드 자동화 시험 없음.
